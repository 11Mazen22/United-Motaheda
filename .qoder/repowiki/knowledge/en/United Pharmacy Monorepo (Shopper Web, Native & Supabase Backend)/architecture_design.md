The repository is an npm workspaces monorepo (`package.json` declares `apps/shopper-web`, `apps/shopper-native`, `packages/*`) where the root orchestrates three layers: (1) client apps — a Vite/Next-based web storefront and an Expo React Native app both consuming shared packages under `packages/`; (2) backend — Deno Edge Functions plus SQL migrations/indexes deployed to Supabase; (3) deployment — separate build/start scripts under `scripts/railway/` invoked via `npm run railway:*` for API, web, and native targets, with `railway.json` pointing at `Dockerfile.ollama` for the backend container, `vercel.json` routing SPA rewrites for the web frontend, and `app.json`/`eas.json` configuring Expo builds. The Supabase backend and the two client apps communicate over HTTP via the Supabase JS client (`@supabase/supabase-js`), while shared TypeScript types and utilities live in `packages/*` so both clients stay in sync with the backend schema.
