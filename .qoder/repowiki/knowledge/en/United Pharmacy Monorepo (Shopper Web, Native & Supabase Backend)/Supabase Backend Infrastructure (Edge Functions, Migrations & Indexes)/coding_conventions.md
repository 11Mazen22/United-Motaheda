- Edge Functions respond with a uniform JSON shape via a local `json(body, status)` helper that sets `Content-Type: application/json` and a shared CORS header block, and reject non-POST requests with 405.
- Auth-aware functions instantiate two Supabase clients: a caller-scoped client (anon key + Authorization header) used solely for JWT verification and role checks, and a separate service-role client used only for privileged DB mutations after authorization passes.
- Privileged database mutations are exposed through PL/pgSQL `SECURITY DEFINER` functions that begin with `IF NOT public.is_manager() THEN RAISE EXCEPTION 'insufficient_privilege'` and end with `REVOKE ALL ... GRANT EXECUTE TO authenticated`.
- Migrations are timestamp-prefixed SQL files placed directly under `supabase/migrations/` and `database/`, with each file owning a single feature or fix and being idempotent-safe via `CREATE OR REPLACE FUNCTION` / `IF NOT EXISTS` patterns.
- Background workers implement an outbox pattern: claim rows via an RPC (`claim_notification_outbox`), process them with retry counters and exponential backoff (`retryAt`), record per-attempt results in `notification_delivery_attempts`, and poll provider receipts to mark final delivery status.
- Request payloads are destructured into typed `Record<string, unknown>` fields and validated defensively (type checks, length bounds, range guards like lat/lng in [-90,90] / [-180,180], clock-skew limits on timestamps) before any DB write.
